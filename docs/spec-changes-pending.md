# Spec changes pending

Places where the code now differs from `docs/front-line-php-rag-spec.md` (version 1.1). The
spec is not edited. Each entry names the spec section, the old rule, the new rule, and the
reason. Issues #62 and #19-#25 produced them. Fold them into the spec at the next version bump.

| # | Spec section | Old rule | New rule | Reason |
|---|---|---|---|---|
| 1 | Section 5, Stage 1, Rules 5 and 6; Section 2.3 | `extract_words` on the pdfplumber text layer; header words deleted by `top < 50` and size 8. | Same, plus a pdfminer pass that records the glyph id of every CID-font character. Glyph ids listed in `parse.glyph_tables` (one JSON file per JetBrains Mono face, generated by `tools/build_glyph_table.py` from the upstream font) replace the text that the PDF's ToUnicode map gets wrong. 1,607 glyphs repaired on the shipped PDF. | The PDF maps the JetBrains Mono ligature glyphs (`->`, `__`, `#[`, and about 640 others) to `=`. Without the repair, code reads `$this=>name` and `=_construct`. `tests/test_glyph_oracle.py` (marker `slow`) checks every body page against PyMuPDF. Issue #48, confirmed in #62 task A. |
| 2 | Section 5, Stage 2, line type table, row `code`; Rule 1 | "Any word in JetBrainsMono or IBMPlexMono" is code; a line is classified by its dominant font. | A mono-dominant line is `code` only when it sits on a code or highlight rectangle, or when every word on it is mono. Otherwise it is prose around an inline identifier and keeps its line type from the other rules. | 28 prose lines held one long inline identifier (`ReflectionProperty::isReadOnly()`) that outweighed the Inter words by character count. They became code blocks, three real code blocks swallowed the sentence before them, and the mis-measured code margin indented 17 code blocks by 3 spaces. CONTEXT.md already defined "Inline code" this way. |
| 3 | Section 5, Stage 2, Rule 1 (lines) | Words on a line are joined with one space. | Two consecutive words join with no space when the horizontal gap between them is under `structure.word_join_max_gap_pt` (1.0 pt). | pdfplumber splits a word at a font change, so `PaidInvoice` and `.` arrive as two words 0.2 pt apart; 127 paragraphs read `PaidInvoice .`. The gap histogram has an empty band from 0.5 to 2.0 pt, so one threshold separates touching from spaced words without a punctuation list. |
| 4 | Section 5, Stage 4, Rule 1; glossary "Section" | A card never says two things from two sections. A section smaller than `min_tokens` is one chunk. | A section under `chunk.min_tokens` joins the previous section of its chapter and takes its title; at a chapter start it joins the next section; alone in its chapter it stays. Never across chapters. The merged heading stays in the text and is listed in `payload.section_titles`. | 52 sections of the book are 30-90 tokens (Chapter 5 alone has 15). As standalone chunks they fail the spec's own "Done when" of no chunk under 120 tokens and have no context to match against. |
| 5 | Section 5, Stage 4 (callouts; scaffold rule "a callout is its own chunk") | A callout is always its own chunk; small chunks beside a callout stay small. | A callout under `chunk.min_tokens` joins the chunk before it, else the one after. The result is a callout only when both sides were callouts. Callouts at or above `min_tokens` stay standalone. | 26 callouts were under 120 tokens: bare YouTube links, a lone `…`, one-sentence tips. One had 0 sparse terms and could never be found by BM25. |
| 6 | Section 5, Stage 4, numbers table; Section 9 `chunk:` | A merge never passes `max_tokens` (600). | New key `chunk.small_merge_max_tokens: 900`. When the small side is under `min_tokens`, the merged chunk may grow up to this value. Must be at least `max_tokens`. | One 42-token callout sat beside a 569-token chunk; the 600 cap left it alone. A card too small to match is worse than one a little too long. Three chunks are now between 600 and 742 tokens. |
| 7 | Section 5, Stage 1, Rule 2; Section 9 (`chunk_config_hash = sha256(canonical json of the chunk section)[:16]`) | `chunk_config_hash` hashes the `chunk` section of `config.yaml`. | It hashes the `parse`, `structure`, `clean`, and `chunk` sections plus the source text of `ingest/s01_parse.py` to `s05_enrich.py`. The git SHA stays a separate manifest field. | A chunker fix with an unchanged `config.yaml` kept the hash, so Stage 1 would have reported "already indexed" and the new chunks would never have reached Qdrant. |
| 8 | Section 5, Stage 8, Rule 1 and Configuration; Section 9 `verify:` | Flag any chapter with fewer than `verify.min_chunks_per_page: 0.5` chunks per page. | Flag any chapter whose covered tokens / clean tokens is under `verify.min_chapter_coverage: 0.99`. A block is covered when its normalized text (lowercase, whitespace collapsed) is a substring of a chunk of the same chapter; chapter titles do not count. Stage 8 reads `data/clean` for this. | Chunks per page measures layout density, not completeness: Chapter 11 (462 tokens over 3 pages) and Chapter 5 (1,630 tokens over 12 pages) were flagged while fully covered. Coverage is the Level 1 rule of issue #62 applied per chapter. |
| 9 | Section 5, Stage 1, Done when ("`Front Line PHP` appears zero times in the parsed output"); issue #62 Level 1 | The book title must not appear in the output. | A whole line of `display_text` must not match a running-header pattern built from the header words that Stage 1 deleted (`\d+ front line php`, `chapter \d+ - <title> \d+`), and no word in `data/parsed` may have the header font size or sit above the header line. | The Foreword contains the sentence "for PHP the answer is here – Front Line PHP". The literal rule fails on real text; the pattern rule catches the header and nothing else. Implemented in `eval/chunk_checks.py`. |
| 10 | Section 5, Stage 5 payload table; Section 10 Chunk payload; Section 5, Stage 2, Rule 7 (`section_title`) | `section_title` is the last heading seen; a chapter intro has an empty title. | `section_title` is always set: a chapter intro carries the chapter title, as the chunk header already did. New payload field `section_titles: list[str]`: the section plus every heading merged into the chunk (change 4), deduplicated, in order. | 73 intro chunks had an empty `section_title`. Merged small sections put a second heading inside a chunk; `section_titles` keeps every heading findable for filters and for the Level 1 sections check. |
| 11 | Section 5, Stage 2, Rule 6 | Only code blocks merge across a page break (and callouts, scaffold decision). | A paragraph that ends a page without a character from `structure.sentence_end_chars` and is not a bullet list (`structure.bullet_chars`) merges with the paragraph that starts the next page, through the hyphen-aware prose join. | 49 of 110 paragraph-to-paragraph page breaks in the book cut a sentence in two. Two chunks started mid-sentence ("$app->make(), we know that...") and 43 held a blank line inside a sentence. |
| 12 | Section 5, Stage 4, Rule 3 (overlap) | The last paragraph of the previous chunk repeats at the start of the next chunk when it has at most 80 tokens. | Only when the previous chunk ends with that paragraph. A chunk that ends in code gives no overlap. | The last paragraph before a code block is its lead-in ("here's what it looks like:"). Repeated without the code, 28 of 207 chunks opened with a dangling colon. |
| 13 | Section 5, Stage 7 (parent store); Section 10 | The store holds `parents` and `chunks`. | A third table `blocks(block_id, parent_id, chunk_id, position, type, text, page_printed)` holds the clean blocks of every chunk in book order, filled from `data/clean` at index time. | Stage 15 must keep code inside fenced `php` blocks with its indentation. Parent and chunk text are plain joins of blocks, so the block boundaries have to be stored (issue #20, open question 3). |
| 14 | Section 6, Stage 15, Rule 5 (label line) | `[S1] Chapter 06: Readonly Properties, p. 75-77` | `[S1] Chapter 06: Readonly Properties > Readonly and clone, p. 75-77`; the section is omitted when it equals the chapter title (chapter intros). | Two blocks from one chapter are told apart by their section; Stage 18 shows the section anyway (issue #20, open question 1). |
| 15 | Section 6, Stage 15, Configuration; Section 9 `context.order` | `order: position | sandwich` | `position` only; `sandwich` is rejected at load until Milestone 7 adds it. New rule: `context.max_tokens` must be larger than `chunk.small_merge_max_tokens`. | The sandwich order is an unmeasured experiment; the budget rule guarantees that the best chunk always fits (issue #20, Part 6). |
| 16 | Section 6, Stage 16, Rule 4 and Configuration; Section 9 `gen:` | The output is exactly `ABSTAIN_TEXT` or an answer with a citation. Configuration lists `prompt_file` and `strict_prompt_file`. | The abstain form tolerates outer whitespace, quotes, emphasis marks, and a final period; the exact text is returned. New keys `gen.repair_prompt_file` (the rewrite note sent with the strict prompt after invalid output) and `gen.max_repair_calls` (per request, shared by Stages 16 and 17). `prompts/registry.json` pins every prompt file's hash. | A harmless "No information found." would otherwise cost a repair call (issue #21, open question 1). The repair note is prompt text, so it lives in `prompts/`, not in code. The registry makes the no-edit-in-place rule testable. |
| 17 | Section 6, Stage 16, Rule 5; Stage 17, Rule 3 | A citation is `[Sn]`. | `[S1, S3]` also counts, as two markers, and spaces inside the brackets (`[ S1 ]`) and the fullwidth brackets `【S1】` are tolerated (gpt-oss writes both; Stage 18 canonicalizes every form to `[S1]`); `(S1)`, `Source 1`, and a bare `S1` are no marker. One parser in `graph/markers.py` serves Stages 16, 17, and 18. | Models write the list form often and the meaning is clear (issue #22, open question 3). |
| 18 | Section 6, Stage 17, Rules 4-7, Configuration, Trace span; Section 9 `output:` | Configuration: `faithfulness_sample_rate`, `code_verbatim`. Spans: `check.citations`, `check.faithfulness`. The repair call reuses Stage 16's note. Judge failure undefined. | New keys `output.judge_prompt_file`, `output.judge_temperature`, `output.judge_max_output_tokens`, `output.repair_prompt_file` (sections `mixed_abstain`, `citations`, `code`, `rewrite`; the repair message names the failed check). New span `check.code` (TOOL) with `rag.code_blocks`, `rag.code_blocks_unmatched`. Code normalization: trimmed lines, no empty lines, one space per run, `...` for `…`; a context without fences (an index built before the `blocks` table) is searched as whole block text (`rag.code_check_plain_text`). The sample is a sha256 of the request id. A judge that fails after the retry, or returns a verdict that is not the JSON shape, abstains with `output.judge_unavailable` when the request is borderline or the harness runs, and otherwise delivers the answer with `rag.judge_error` on the span; a placeholder judge model is a configuration error and propagates. A verdict that says `supported: true` but lists claims is read as not supported. A bracket group that looks like a label but is not an accepted marker (`[S1-S9]`, `[s9]`) fails the citation check. Fences of three or more backticks or tildes are read; an unclosed fence runs to the end of the answer. Code outside a fence is not checked (spec rule 6). `rag.rejected_answer` is recorded only when `trace.capture_content` is true, like every other content attribute. | Issue #22, Parts 2, 3, 6 and open questions 1 and 4. Every tunable comes from `config.yaml`; a named failure is fixed more reliably; the old live index serves unfenced context until the next `flp ingest --force`. |
| 19 | Section 10, `Source`; Section 6, Stage 18, Rule 1 | `Source.chunk_id: str`. | `Source.chunk_ids: list[str]`: every chunk of the cited block. The section title of a source joins the section titles of the block's chunks with " + ". The score is the highest rerank score among the block's chunks. `[S1, S3]` in the answer becomes `[S1][S3]`; labels are not renumbered. | One context block can hold several chunks (a whole parent); the client needs them all for a page range and the harness for citation accuracy (issue #23, open questions 1 and 5). |
| 20 | Section 6, Stage 18, Rules 2 and 3; Section 9 `api:`; Section 6, Stage 9 | Status `error` responses are the short `{status, trace_id, detail}` body. The log line holds the fields of Rule 3. | New key `api.error_text`, never the abstain text (checked at load). Every error that leaves the graph early (400, 504, 500, 501) answers with the full `Response` shape built by the Stage 18 builder (status `error`, `api.error_text`, no sources, versions) plus `detail`; only a 422 validation error keeps the short body. The summary log line also carries `config_hash`, `n_sources`, `repair_calls`, `borderline`, and is written for error requests too. `timings_ms` comes from the graph wrapper per span name; `response.build` is in the state but not in the record it builds. The CLI command `flp ask` runs the graph; the Milestone 2 chunk listing moved to `flp retrieve`. Limit: an error that leaves the graph early reports the totals known before the error (the state the graph started from: zero tokens and cost, no timings), because LangGraph does not return partial state on an exception; the ERROR line and the trace hold the rest. The debug field of an error names only the exception class and the safe detail. | One shape for every reader (issue #23, Parts 1 and 4, open question 2). |
| 21 | Section 4.2 (model providers); Section 9 `gen:`, `output:`, price table; Section 6, Stage 16 Configuration | Providers `anthropic`, `openai`, `ollama`; `gen.max_output_tokens: 800`; no reasoning setting. | New provider `groq` (`groq:<model>`): the OpenAI chat protocol at `GROQ_BASE_URL` with `GROQ_API_KEY`, both from `.env`. Shipped models `groq:openai/gpt-oss-120b` (generator) and `groq:openai/gpt-oss-20b` (judge, query), price rows 0. New keys `gen.reasoning_effort` and `output.judge_reasoning_effort` (`low`/`medium`/`high`/unset), sent to OpenAI-protocol clients only. `gen.max_output_tokens` is 2000 and `output.judge_max_output_tokens` 1200, because a reasoning model's thinking counts toward the completion limit (the first live run was cut at 800 and abstained with `gen.invalid_output`). | A free tier that reaches the latency and format quality the strict prompts need; the earlier Groq Llama names were retired and the key reaches the gpt-oss models. |
| 22 | Appendix D (`cli.py`); Section 9 (no `cli` section); Section 11, Milestone 3 step 4 | `flp ask` answers; no client settings, exit codes, or JSON output are specified. | `flp ask` is an HTTP client of `POST /ask`. New section `cli:` with `api_url` (overridden by `--api-url`, then `FLP_API_URL`) and `timeout_s`, which must exceed `api.timeout_s` so the server's 504 with its trace id reaches the user. Exit codes 0 answered, 2 no information, 1 error or no API. `--json` prints the raw record; `--stream` prints pieces and a withdrawn note; `--retrieve-only` and the `flp retrieve` command run the Milestone 2 local retriever. `flp eval` and `flp calibrate` print "Available from Milestone 6" and exit 1. | Issue #24: one pipeline, one entry point; scripts need a signal that tells an answer from an abstain. |
| 23 | Section 6, Stage 12, Rules 1-3, 5, 6; Section 10 `Candidate`, `StandaloneQuery`; Section 5, Stage 6 | `QdrantVectorStore` calls per mode in `RunnableParallel`; RRF output has `fused_score` and a provenance list (retriever and variant); every variant goes to both retrievers; siblings are added to the list. | Direct `query_batch_points` calls: one batch per retriever with one request per variant, the same request filter on every list. Sparse queries use the BM25 model's query mode (a weight of 1 per term; Qdrant adds the IDF), never its document mode. The keyword variant goes to the sparse retriever only (issue #25, open question 1); `StandaloneQuery.keyword_variant` carries it. Provenance entries carry the rank: `dense:v0:r3`, `sparse:v1:r1`, `code_group`. New field `Candidate.scores`: the best raw score per retriever (`rag.scores_all` on the span); the rerank stub reads the dense cosine from it until #26. Ties break by best single rank, then chunk id. Siblings join after the cut, so the list can exceed `top_k_fused` (open question 4). A failing sparse side is an error, not a dense-only answer (open question 2). Child spans: one per retriever with the lists as attributes (`rag.n_queries`, `rag.hits_per_list`, `rag.top_score_per_list`), plus `retrieval.fuse` (`rag.rrf_k`, `rag.n_in`, `rag.n_out`). Chunk text is not recorded on the documents: Qdrant holds no text, and a store read at this stage would cost latency for a debug view. | Issue #25. One batch per step keeps the stage under 100 ms; the query mode keeps BM25 scores on the scale Stage 7 indexed; the scores field gives the gate a meaningful stand-in before the reranker lands. |
